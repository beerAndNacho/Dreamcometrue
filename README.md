# Macro Invest 4.5.1 — Intelligence Observatory / 글로벌 투자 관측소

개인용 로컬 또는 HTTPS 호스팅 웹 서비스. FastAPI + SQLAlchemy + PostgreSQL(Docker) 또는 SQLite(간편 실행) + 순수 HTML/CSS/JS. 38개 지표 수집 및 분석, 우주 관측소 테마, 관리자 콘솔, 지표 품질 확인, 리포트 다운로드, 서버 포트폴리오 저장을 지원합니다. 거래 주문은 실행하지 않습니다.

## 4.5.1 KOSIS 연동 수정

- KOSIS 인증키는 발급된 원문 그대로 입력합니다. `+`, `/`, `=`가 포함된 키를 허용하며 HTTP 요청에서 안전하게 인코딩합니다. 실제 키는 공유하거나 GitHub에 올리지 마세요.
- 빈 통계표 설정의 기본값: 선행 `orgId=101&tblId=DT_1C8015&itmId=T1&objL1=A03`, 동행 `orgId=101&tblId=DT_1C8015&itmId=T1&objL1=B03`. 공개 조회 사례를 기반으로 한 설정이며 실제 응답의 지표명/코드/주기를 확인해 다른 계열을 저장하지 않도록 검사합니다. 기존에 직접 지정한 설정은 유지됩니다.
- `/admin` → KOSIS의 **기본 순환변동치 설정 적용** → 설정 저장 → 연결 검사. 기존 설정이 비어 있다면 키 저장만으로도 기본 쿼리가 적용됩니다. 정상 응답에는 조회 건수와 최근 관측월/값이 표시됩니다. 연결 검사는 DB에 쓰지 않습니다. 성공 후 전체 수집을 실행합니다.
- 표준 JSON을 받기 위해 `jsonVD=Y`를 지정합니다. 오류 코드 10/11(인증), 20/21(변수), 30/31(자료/기간), 40~42(제한), 50(공급처 서버)을 구분하며 원본 오류 본문 및 키는 표시하지 않습니다. HTTP/네트워크 오류 및 JSON 형식 오류도 별도 안내합니다.
- 오류 11은 KOSIS 공유서비스의 활용신청 승인 상태, 키의 유효기간, 정확한 발급 원문을 확인하세요. 20/21/30은 통계표 설정 및 수록기간을 확인하세요. HTTP 오류는 서버에서 외부 HTTPS 접속 가능 여부와 공급처 상태를 확인하세요.
- 기존 이력 삭제는 자동 수행하지 않습니다. 통계표가 바뀌거나 출처 확인 오류가 생기면 DB/CSV 백업 및 원자료 확인 후 기존의 명시적 초기화 절차를 사용하세요. `DEMO_MODE=1`에서는 실제 연결 검사가 금지되므로 실데이터 모드인지 확인하세요.
- [KOSIS 공식 API 안내](https://kosis.kr/openapi/devGuide/devGuide_0201List.do), [오류 유형 FAQ](https://sso.kosis.kr/openapi/community/community_0401List.do), [통계표](https://kosis.kr/statHtml/statHtml.do?orgId=101&tblId=DT_1C8015), [코드 공개 조회 사례](https://github.com/Seungwoo321/eidc/). 실계정 응답 미검증: 연결 검사에서 실제 지표명·최근값을 원자료와 대조하세요.

## 4.5 신규: 투자 분석센터와 경제 캘린더

`/intelligence` (관리자 로그인 필요)에서 일간/주간 관측 리포트, 관심종목 공개 시세·수급·연간 공시·배당 근거, 규칙 기반 조건부 시나리오, 선택형 AI 해석 및 과거 저장 리포트를 이용합니다. 메인 대시보드와 국내 증시 화면 메뉴에도 연결했습니다.

### 경제 캘린더
- BLS 공식 구독(https://www.bls.gov/schedule/news_release/bls.ics): CPI, 고용 등 미국 노동통계국 발표 시각. 수동 갱신 또는 관리자 `BLS_AUTO_REFRESH` 활성화 시 기존 경제지표 수집과 함께 최대 24시간에 한 번 자동 갱신. 실제 서버가 실행되고 수집이 동작해야 합니다. BLS 원본의 일정 변경은 다음 갱신에서 반영하며 실패 시 마지막 성공 목록을 유지합니다. 8일 초과/오류 시 재확인 경고. 일반 VEVENT(UTC, ET, 날짜만 있는 휴일 제외)를 파싱하며 반복 이벤트/지원하지 않는 시간대 등은 실패 처리합니다. 실제 BLS 네트워크 호출은 미검증입니다.
- BEA/PCE, FOMC, 한국은행/KOSIS/OECD 등: 공식 일정을 확인해 수동으로 등록·수정·삭제합니다. 허용된 공식 HTTPS 도메인 및 쿼리/프래그먼트가 없는 URL만 지원합니다. 원문 일치 여부는 사용자 확인이 필요합니다. 다른 출처의 컨센서스는 자동 조회하지 않습니다.
- 시간은 UTC로 저장하고 KST 표시/카운트다운. 미국 동부 및 영국 현지 시각은 IANA 시간대 규칙을 적용하며 서머타임 전환의 모호/존재하지 않는 시각은 거부합니다. 발표 예정, 시간 경과·결과 미확인, 발표, 취소를 구분합니다. 실제/이전/직접 입력 예상은 동일 단위로 입력하며 차이 = 실제 − 예상. 자동 발표값 연결/시장 반응 분석은 미구현입니다.

### AI 투자 해석 및 비용 관리
1. `/admin#aiSetup`에서 OpenAI / Gemini / Claude 중 선택, 키와 해당 계정에서 사용 가능한 텍스트 모델 ID 직접 입력. 기본 OFF. 저장된 키는 서버 암호화 설정만 사용하고 브라우저에는 등록 여부만 반환합니다.
2. `/intelligence`에서 기간(일간/주간), 범위(전체 시장/등록 종목) 선택 후 현재 자료 조회. 주간 비교는 7~14일 전 실제 저장 스냅샷이 있는 경우만 표시하며, 없는 경우 보류합니다.
3. 규칙 리포트 저장은 AI 호출 없음. AI 해석은 공개 근거 외부 전송/과금 동의 후 버튼을 누를 때만 호출합니다. 자동 유료 실행, 자유 프롬프트, 외부 검색 도구, 주문 기능은 없습니다. 데모에서는 외부 호출 금지.
4. 전송은 신선한 공개 데이터의 ID·명칭·수치·단위·관측일·변화와 선택 종목코드로 제한합니다. 개인 보유수량/매입가/자산/메모/사용자 등록 일정·CSV/비밀번호는 전송하지 않습니다. API 키는 인증 헤더에만 사용. 제공처 요금·개인정보 처리 정책 및 데이터 라이선스 확인 필요. OpenAI Responses API에는 `store=false` 지정(제공처의 별도 보관 정책까지 제거한다는 뜻은 아님).
5. AI 출력은 근거 ID 존재, JSON 구조, 항목 길이, 숫자/URL/HTML 금지 검사를 거칩니다. 숫자 및 출처는 서버 저장 근거에서만 표시합니다. 형식 오류/제공처 오류 시 규칙 자료를 보존하고 AI 해석은 숨깁니다. 의미상 사실성, 투자 타당성을 보장하지 않습니다. 뉴스·컨센서스·목표주가를 자동 생성하지 않습니다.
6. KST 일일 외부 호출 시도 상한(기본 3, 1~20), 최대 출력 토큰(기본 1200, 256~3000), 동일 관측 스냅샷 성공 리포트 재사용, 사용량 및 실패/중단 이력. 실패도 한도에 포함, 자동 재시도 없음. 사용량 누락 시 미확인 표시. 토큰/횟수 제한은 실제 청구 상한이 아니며 비용은 제공처에서 확인합니다. 로컬 DB에 리포트 스냅샷과 사용량을 저장하며 기존 거시 위험 점수/배분 규칙은 변경하지 않습니다.

공식 API 규격: [BLS 일정](https://www.bls.gov/help/hlpiCAL.htm), [OpenAI Responses](https://developers.openai.com/api/reference/resources/responses/methods/create), [Gemini GenerateContent](https://ai.google.dev/api/generate-content), [Claude Messages](https://platform.claude.com/docs/en/api/messages/create). 실제 외부 API 계정, 모델별 호환성과 비용, 실데이터 단위 및 Render/Docker 환경은 직접 검증해야 합니다.

## 1. Windows에서 가장 빠르게 실행

Python 3.11 이상 설치 후 ZIP 파일을 압축 해제합니다.

- `start-demo.bat`: 가상 데이터로 화면과 계산 기능 확인.
- `start-live.bat`: 실제 데이터 모드로 실행 (SQLite). 처음에는 수집 데이터가 없습니다.
- Mac/Linux: `sh start-demo.sh` 또는 `sh start-live.sh`.
- 브라우저에서 `http://127.0.0.1:8000` 접속.
- 관리자: `http://127.0.0.1:8000/admin` 접속. 사용자명 `admin`.
- 최초 시작 시 생성되는 비밀번호: `data/settings/live/admin-password.txt` 또는 데모 `data/settings/demo/admin-password.txt`. `.env`에 `ADMIN_PASSWORD`를 12자 이상 지정하면 파일 대신 그 비밀번호를 사용합니다. 영문/숫자 조합의 충분히 긴 무작위 비밀번호를 권장합니다.
- 서버 종료: 실행 터미널에서 Ctrl+C. 두 모드를 동시에 같은 포트에서 실행하지 마세요.

데모와 실데이터는 DB 및 관리자 설정을 분리합니다. 데모는 가상 SQLite DB를 사용하고 실제 외부 API 검사 및 수집이 차단됩니다. 데모에 등록한 키는 실데이터 모드로 넘어가지 않습니다. 가상 데이터 초기화는 서버 종료 후 `data/demo.db` 삭제. 실제 DB는 삭제하지 마세요.

## 2. Docker + PostgreSQL 실행

Docker Desktop 또는 Docker Engine/Compose v2를 설치합니다. 프로젝트 디렉터리에서 `.env.example`을 `.env`로 복사합니다.

```powershell
Copy-Item .env.example .env
```

Mac/Linux: `cp .env.example .env`.

`.env`의 `DEMO_MODE=0` 확인, 선택적으로 `ADMIN_PASSWORD`(12자 이상) 및 `POSTGRES_PASSWORD` 설정. API 키는 관리자 화면에서 등록할 수 있으므로 `.env`를 직접 수정할 필요가 없습니다. 초기 자동 수집은 OFF입니다.

```bash
docker compose up --build -d
docker compose logs -f app
```

`http://127.0.0.1:8000` 및 `/admin`으로 접속합니다. `ADMIN_PASSWORD`를 직접 설정하지 않은 경우, 다음 명령으로 최초 생성한 비밀번호를 확인할 수 있습니다.

```bash
docker compose exec app cat /app/data/settings/live/admin-password.txt
```

데모 모드에서는 경로의 `live`를 `demo`로 바꿉니다. 비밀번호를 다른 사람과 공유하지 마세요. `docker compose down`으로 종료합니다. PostgreSQL 데이터와 설정은 named volume(`pgdata`, `demodata`)에 보존됩니다. `down -v`는 저장 자료와 암호화 키까지 제거하므로 피하세요. 기존 1.0 Docker 배포의 DB/볼륨을 유지하려면 기존 Compose 프로젝트 이름을 유지하고 먼저 백업하세요. 새 폴더에서 실행하면 기본적으로 새 볼륨이 만들어집니다.

## 3. 관리자 화면 사용법

1. `/admin` 접속 → 브라우저 인증 창에서 `admin` / 위의 비밀번호 입력.
2. FRED, ECOS, KOSIS 키 입력 및 KOSIS 통계표 URL 설정 → **설정 저장**. 공란인 키는 유지되고, '저장 키 제거' 체크 후 저장하면 환경변수 키도 사용하지 않습니다. 기존 키는 화면으로 반환되지 않습니다.
3. **연결 검사**: 저장된 설정으로 최근 약 8개월간 표본 원자료를 조회. FRED CPI, ECOS 6개 지표, OECD 3개 CLI, KOSIS 2개 순환변동치 검사. 실제 응답을 받지만 DB에는 쓰지 않습니다. 전체 시리즈 성공을 보장하는 검사는 아닙니다.
4. 조회 시작일, 자동 수집 여부, 한국 시간 기준 수집 시간 설정 → **일정 저장**. 처음에는 자동 수집 OFF.
5. **지금 전체 수집** 실행 → 하단 지표별 상태/최근 성공 시각/최근 30개 실행 이력 확인. 서버를 켜 둔 경우 매일 설정한 시각 이후 하루 한 번 시도합니다. 설정 변경은 다음 검사 또는 수집부터 적용되며 재시작 불필요합니다. API 검사/수집 중에는 설정 저장과 다른 수집이 차단됩니다.
6. 대시보드 이동 → 핵심 지표, CLI 차트, 시장 위험도, 모델 배분을 확인합니다. 필수 데이터가 없거나 오래됐으면 모델 신호가 보류됩니다.

### API 키 발급 및 통계표 설정

| 제공처 | 지표 수 | 키 | 안내 |
|---|---:|---|---|
| FRED | 27 | 필요 | https://fred.stlouisfed.org/docs/api/api_key.html |
| OECD | 3 | 불필요 | https://data-explorer.oecd.org/ |
| 한국은행 ECOS | 6 | 필요 | https://ecos.bok.or.kr/api/ |
| KOSIS | 2 | 필요 (기본 통계표 자동 설정) | https://kosis.kr/openapi/ |

사용자 지정 통계표가 필요한 경우 KOSIS OpenAPI '통계자료 > 통계표선택(URL 생성)'에서 경기종합지수의 전국 월간 선행종합지수 **순환변동치** 한 항목을 선택합니다. 생성 URL 전체 또는 쿼리만 선행지수 입력란에 붙여 넣으세요. 동행종합지수 순환변동치도 동일하게 설정합니다. URL의 `apiKey`와 기간은 저장하지 않고 별도 API 키 입력 및 프로그램 조회 기간을 적용합니다. 필수 파라미터는 orgId, tblId, itmId, objL1입니다. 4.5.1은 위 기본 통계표를 제공하며 실제 계정의 응답 검증이 필요합니다. 통계표를 변경하고 기존 데이터가 있을 때에는 기존 해당 지표 관측값/수정 이력 삭제를 명시적으로 확인받습니다. 변경 전 CSV/DB 백업을 권장합니다. 삭제하면 해당 지표를 다시 수집해야 합니다.

FRED 공식 관측 API: https://fred.stlouisfed.org/docs/api/fred/series_observations.html
ECOS 코드: 기준금리 722Y001/0101000, 국고채 3/10년 817Y002/010200000 및 010210000, 원/달러 731Y001/0000001, 코스피/코스닥 802Y001/0001000 및 0089000. OECD CLI: amplitude adjusted / OECD harmonised, OECD.SDD.STES / DSD_STES@DF_CLI. 제공처의 실제 키·데이터 응답 확인 필요. 외부 API 및 시리즈 제공 범위/이용약관은 바뀔 수 있습니다.

### 설정과 보안

- API 키는 서버의 `data/settings/{live,demo}/settings.enc`에 Fernet 인증 암호화로 저장. `settings.key`는 복호화 키이므로 암호문과 함께 안전하게 백업하되 공유하지 마세요. 파일 접근 권한은 POSIX에서 0600으로 생성되며 Windows는 OS 파일 권한에 따릅니다. 동일 호스트에서 파일에 접근 가능한 사용자는 복호화할 수 있습니다.
- `.env`는 최초 기본값이며 관리자 저장값이 우선합니다. `ADMIN_PASSWORD`, `DATABASE_URL`, `DEMO_MODE`, `SETTINGS_DIR`은 환경변수 설정입니다. 관리자 화면에서 비밀번호나 DB 주소를 바꾸지 않습니다.
- 관리 페이지/API는 HTTP Basic 인증, 관리자 변경 요청은 커스텀 헤더/Origin 확인, 호스트 검증, no-store를 적용합니다. 로컬 모드는 localhost에만 바인딩합니다. 호스팅 모드는 HTTPS 진입점과 전 페이지 Basic 인증을 전제로 합니다. 단일 개인 사용자용이며 다중 사용자/RBAC/MFA는 구현하지 않았습니다. 브라우저가 인증 정보를 기억할 수 있으니 공용 컴퓨터에서 사용하지 마세요.
- localhost에만 포트를 바인딩합니다. Docker 내부는 0.0.0.0이지만 호스트 공개는 127.0.0.1입니다. 인터넷에 그대로 노출하지 마세요. 관리자 API 인증은 대시보드 읽기 API와 분리되며, 대시보드 읽기 및 브라우저 보유종목은 로컬 PC 사용자에게 보일 수 있습니다. 서버 포트폴리오 API에는 로컬에서도 관리자 인증이 필요합니다.
- 설정을 바꾸기 전 `data/` 및 DB 백업. 설정 파일이 손상되거나 키를 잃으면 암호문을 복구할 수 없습니다. 수동 재설정 전 암호문/키를 별도 백업하세요.

## 4. 모델 규칙 (검증되지 않은 가설)

경기 국면: CLI 또는 순환변동치 기준 100과 3개월 변화량을 이용한 단순 모델. `abs(변화량)<0.01`이면 보합. 100 미만 상승=회복, 100 이상 상승=확장, 100 이상 하락=둔화, 100 미만 하락=하강. 공식 경기침체 판정이 아닙니다.

| 국면 | 주식 | 채권 | 현금 |
|---|---:|---:|---:|
| 회복 | 70 | 20 | 10 |
| 확장 | 65 | 25 | 10 |
| 둔화 | 45 | 35 | 20 |
| 하강 | 30 | 40 | 30 |

위 비중은 사용자 지정값이 아니라 개발 시 설정한 설명용 가설입니다. `app/analysis.py`의 `ALLOC`에서 변경 가능.

미국 시장 위험 점수: VIX 20 이상 15점, 30 이상 30점. 하이일드 OAS 4%p 이상 15점, 6%p 이상 30점. S&P 500 200거래일 평균 하회 20점. CLI 둔화 10점, 하강 20점. 40점 이상이면 주식에서 현금으로 10%p 이동, 70점 이상이면 20%p 이동. 저점수는 안전·수익 보장이 아닙니다. 채권 금리 위험/통화 위험 및 개인 자금 필요는 반영하지 않습니다. 지표가 없거나 수집 실패 또는 관측일이 오래된 경우 위험도 및 비중을 보류합니다. 관측일 허용 지연은 일간 7일, 주간 21일, 월간 75일, 분기 190일로 정한 단순 규칙입니다.

물가(CPI/PCE), M2, 산업생산, 소매판매는 원자료의 전년 동월 대비 증가율, 고용 증감은 전월 차분입니다. `직전 대비`는 화면에 표시되는 값 간의 차이입니다. 전년비는 정확히 12개월 전 관측값이 없으면 계산하지 않습니다.

## 5. 종목 적정가와 보유종목

양수 EPS × PER로 보수/기준/낙관 3개 시나리오를 계산합니다. 실적 전망과 현재가는 수동 입력입니다. 적자기업, 금융·지주사 등에는 별도 모델이 필요합니다. 보유종목은 브라우저 localStorage에 저장되며 통화별 평가액만 합산됩니다. 실시간 시세 및 애널리스트 컨센서스, 환율 자동 환산, 주문 실행, 실시간 포트폴리오 리밸런싱은 이 버전에 없습니다.

## 6. 백테스트 (탐색용)

월말 기준 동일 통화의 배당/이자 재투자 총수익 지수(주식·채권·현금)를 CSV로 준비하세요. 월은 `YYYY-MM` 형식, 연속된 최소 13개 월을 입력합니다. 숫자는 천단위 쉼표 없이 양수로 넣습니다. 모든 월은 완료된 과거 월이어야 합니다.

```csv
month,stock,bond,cash
2023-01,100.00,100.00,100.00
2023-02,102.00,100.40,100.30
2023-03,101.50,101.20,100.60
```

위 3개 행은 형식 설명용이며 실행에는 최소 13개월이 필요합니다. 첫 수익 구간 직전 월에서 설정한 발표 지연(최소 2개월)을 뺀 시점의 CLI로 다음 월 비중을 결정합니다. 실제 월별 자산 수익률과 리밸런싱 거래비용을 적용하고 주식 100% 보유와 누적수익률·CAGR·월말 최대낙폭을 비교합니다. 미국 CLI 기본 비중만 검증하며 VIX/HY/200일선 오버레이는 제외됩니다. 중간 CLI 자료 누락 또는 보합이면 기간을 조정해야 합니다. 수정된 CLI를 사용하기 때문에 최초 발표값 기준의 진정한 시점별 백테스트가 아닙니다. 비용은 회전율 기반 근사이며 세금·환율·슬리피지 미반영입니다. 과거 수정 이력 전체는 ALFRED 등 별도 자료가 필요합니다.

## 7. 추가된 포트폴리오 기능

주식·채권·현금 보유금액을 입력하고 시장 모델 또는 직접 지정 비중과 비교합니다. 리밸런싱 차이는 산술값이며 세금과 거래비용을 반영하지 않습니다. 스트레스 테스트는 반도체·AI/기타 주식/채권의 가정 수익률과 현재 비중을 사용합니다. 현금 수익률 0%, 환율·레버리지 경로·거래비용 미반영. 가상 기본 입력값입니다. 개별 보유종목은 브라우저 localStorage에 저장됩니다. 서버 저장 버튼을 누르면 관리자 인증 후 보유종목과 자산배분/스트레스 테스트 입력값을 별도 서버 DB에 저장할 수 있습니다. 불러오기는 기존 브라우저 입력을 덮어쓰므로 확인창을 거칩니다. 서버의 저장본은 1개이며 다중 사용자 계정이나 버전 관리가 없습니다. 서버 DB의 포트폴리오 값은 별도 암호화하지 않으므로 DB와 볼륨 접근 권한을 보호하세요.

## 10. 3.0 개선사항 및 운영 체크

- 대시보드는 최대 최근 420개 원자료만 조회하여 계산합니다. 상세 차트/CSV는 별도 조회하며 YoY/MoM 계산에 필요한 추가 관측값을 확보합니다. 1,200개 이상 긴 차트는 버킷별 최소/최대값을 보존해 그립니다. SQLite WAL 및 대기 시간 설정으로 읽기/쓰기 충돌을 완화합니다.
- 자동 수집은 정상 일간 지표의 최근 45일(누락 기간이 길면 더 긴 기간)과 수정 중첩 구간을 갱신합니다. 일요일에는 전체 재수집, 수동 수집은 항상 전체, 새 지표/설정 변경/직전 실패도 전체 조회입니다. 월간·주간·분기 및 OECD 데이터는 전체 조회합니다. 전체 조회에도 공급처 제한이 있어 요청 시작일보다 뒤의 데이터만 제공될 수 있습니다. 오래된 기간의 원자료가 삭제되거나 제공처 정책이 바뀌어도 이전 저장값을 자동 삭제하지 않습니다.
- 지표 품질(신선한 관측값, 미수집, 오래됨/오류), 개별 관측일, 수집 메시지, 실제 최근 30개 값의 미니 차트를 표시합니다. 리포트 저장 버튼은 최신 수집값과 모델 근거를 TXT로 내려받습니다. AI 뉴스 생성, 자동 리포트 발송은 포함하지 않습니다.
- KOSIS 통계표 출처를 해시로 기록합니다. 2.x에서 이미 수집한 KOSIS 이력에는 출처 해시가 없으므로 3.0에서는 해당 자료를 신호로 쓰지 않고 수집을 보류합니다. **기존 해당 지표 데이터를 CSV/DB로 백업한 후** 관리자에서 이력 초기화(삭제 확인)하고 정확한 통계표를 재설정해 전체 수집하세요. 외부 환경변수로 통계표가 변경되거나 설정/DB 중 일부 저장에 실패해도 다른 통계표 자료를 섞지 않도록 막습니다.
- ECOS 새 코스피·코스닥 통계코드 및 기존 금리 코드는 실제 키로 확인해야 합니다. 응답의 통계 코드와 항목명(제공되는 경우)을 검사하며 불일치 시 실패 표시합니다. FRED 하이일드 OAS는 2026년 4월부터 3년 관측값만 제공된다는 시리즈 안내가 있습니다(https://fred.stlouisfed.org/series/BAMLH0A0HYM2). 공급처별 자료 재배포 조건을 준수하세요. 개인 비공개 운영을 전제로 합니다.
- 설정/수집/포트폴리오 변경 요청에는 기존 인증/Origin 검증과 1MB 요청 본문 제한이 적용됩니다. 호스팅 응답에는 HSTS를, 일반 페이지에는 CSP를 추가합니다. Swagger 문서 경로는 CDN 및 초기화 스크립트가 필요한 관계로 일반 CSP 적용 대상에서 제외했습니다. 상용 보안 감사나 다중 사용자를 위한 접근 제어는 제공하지 않습니다.
- 기존 2.x 데이터/설정을 보존하려면 동일한 DB 경로와 설정 디렉터리, Docker 볼륨/프로젝트 이름을 유지하세요. 새 테이블은 최초 실행 시 생성됩니다. **먼저 서버를 정지하고 DB 및 settings.key/settings.enc를 백업하세요.** 데모 DB는 별도이며 새 지표는 기존 데모 DB에도 추가됩니다.


## 11. 4.0 — 사용 편의성과 설명 기능

### 매일 사용하는 순서
1. 관리자 콘솔의 **MISSION CHECKLIST**에서 API 키 및 KOSIS 통계표 등록 → 저장 → 표본 연결 검사 → 전체 수집 → 자동 수집 일정을 확인합니다. 체크리스트는 키 등록 및 수집 상태를 보여주는 안내입니다. 연결 검사는 자동 성공 판정하지 않으므로 직접 실행해야 합니다.
2. 대시보드 상단의 아침 브리핑에서 핵심 3줄을 확인하고, 전체 해석/이전 날짜 변경사항을 펼칩니다. 외부 뉴스나 AI 예측은 아닙니다. 표시된 관측값과 기존 위험 모형의 규칙에 근거한 설명입니다.
3. 각 지표의 이름 또는 `차트·설명`을 눌러 정의, 상승·하락 의미, 주의사항, 원출처와 실제 날짜별 값을 확인합니다. 학습센터에는 현재 지원하는 38개 지표 전체의 설명과 검색을 제공합니다. 즐겨찾기(별표)를 누르면 기본 시장 카드에 해당 지표가 추가되고, 모니터에서 즐겨찾기/신선한 자료만 필터링할 수 있습니다. 즐겨찾기는 해당 브라우저에 저장되며 서버 포트폴리오와는 별도입니다.
4. 경기순환 지도는 미국·한국·영국 OECD CLI의 100 기준 위치와 정확히 3개월 전 대비 변화로 최근 최대 6개 월의 관측점 및 경로를 그립니다. 월이 비면 선을 연결하지 않습니다. 오래되거나 확인 불가한 국가, 수집 중에는 현재 위치를 표시하지 않습니다. 과거 경로는 현 시점의 수정된 자료이며 당시 발표 시점의 값이 아닙니다. 보합은 기존 모델의 0.01pt 기준을 따릅니다.
5. 위험도 시뮬레이터에서는 VIX, 하이일드 OAS, S&P500 200거래일 평균 대비, 미국 CLI 국면을 입력해 계산하거나 최신 확인 모델값/금융위기 가정을 사용할 수 있습니다. `score_inputs()`는 라이브 계산과 시뮬레이션이 공유합니다. 시뮬레이션은 데이터나 포트폴리오를 변경하지 않습니다. 소수점 표시값이 아닌 내부 원래 입력값으로 경계값을 평가합니다.
6. 지수와 가격의 직전 관측값 대비 포인트(또는 원화 등) 및 변화율을 구분합니다. 금리와 물가상승률의 변화는 %p로 표시합니다. 관측일 탐색 슬라이더는 실제 저장된 날짜만 선택하고, 해당 날짜가 없는 계열은 —로 표시합니다. 곡선 보간값을 생성하지 않습니다.
7. 보유종목 편집 버튼으로 입력란을 불러와 수량·가격·예상 EPS·PER을 바꾼 뒤 저장합니다. 동일 종목명과 통화는 덮어쓰며 이름/통화를 변경하면 새 종목으로 저장되므로 기존 종목은 필요시 삭제합니다. 최신 수집 상태가 유효한 USD/KRW를 사용해 수동 입력 KRW/USD 주식 평가액을 원화 환산합니다. GBP 보유분 또는 신선한 환율이 없는 경우 전체 환산을 보류합니다. 실제 거래소 시세, 투자 손익 및 환전비용은 자동 연동하지 않습니다.

### 스냅샷 / 운영 안전
- 새 DB 테이블 `daily_market_snapshots`는 시작 시 자동 생성됩니다. 기존 관측값·포트폴리오·관리자 설정 테이블을 삭제하거나 변경하지 않습니다. 기존 DB와 설정 파일을 먼저 백업하세요.
- 실제 수집이 정상 또는 일부 성공으로 끝나면 해당 한국 날짜의 마지막 완료 스냅샷을 저장합니다. 같은 날짜 재수집은 마지막 저장값을 교체합니다. 다음 날짜에는 가장 최근의 **이전 날짜에 저장된** 스냅샷과 비교합니다. 휴일이나 누락된 날짜가 있으면 그 이전 실제 저장 날짜를 사용합니다. 이전 스냅샷이 없으면 표시하지 않으며 3.x의 과거 날짜를 재구성하지 않습니다.
- 비교는 양쪽 스냅샷에서 신선하고 출처가 동일한 자료로 제한합니다. 관측일 갱신(값이 같더라도 포함)과 동일 관측일 값 수정을 구분합니다. 누락/오류/출처가 바뀐 자료는 비교에서 제외됩니다. 스냅샷은 전체 과거 최초 발표값 데이터베이스가 아닙니다. 스냅샷 저장 실패는 수집 자체의 데이터를 손상시키지 않으며 서버 로그에 경고합니다. 데모는 별도 DB에서 최초 실행 시 가상 스냅샷을 저장합니다.
- 수집 중에는 서로 다른 수집 시점의 신호를 섞지 않도록 위험 점수 및 모델 배분·브리핑 비교를 보류합니다. 현재도 하나의 서버 프로세스/worker를 전제로 합니다.
- 새 API: `GET /api/guide`, `GET /api/guide/{sid}`, `POST /api/scenario`. 기존 API 및 CSV/TXT 형식과 포트폴리오 저장 구조는 보존하고 대시보드 JSON에 비교값·브리핑 필드를 추가했습니다. TXT 리포트 뒤에 브리핑과 변화 내역이 추가됩니다.
- 새 파일: `app/guide.py`(지표 설명), `app/dashboard_data.py`(공통 대시보드 계산), `app/briefing.py`(스냅샷·규칙 설명), `app/static/orbital-v4.js`와 `orbital-v4.css`(UI), `tests/test_v4.py`(회귀 테스트).
- 미구현: 실시간 개별주가·예상 EPS·SOX/FTSE100·기관 수급 자동 연동, 자동 경제 캘린더 및 예상치, AI API, 푸시 알림, 자동 백업/복원, 최초 발표값 백테스트. 앱 설치(PWA)와 관리자 모델 편집은 인증·캐시·전략 버전 관리 설계 후 추가할 항목입니다. 현재 ChatGPT 아침 리포트 예약과 프로그램은 별개입니다.


## 12. 4.1 국내 증시 관측소 (선택형 데이터 연결)

대시보드의 **국내 증시 · 수급** 또는 `/kr-market`을 열면 코스피·코스닥 외국인/기관/개인 순매수, 일별/누적 그래프, 최근 5·20·60개 유효 관측일 합계, 외국인 연속 순매수/순매도와 기금·증권·투신 세부 수급을 볼 수 있습니다. 관측일과 상태를 반드시 확인하세요. 기존 38개 경제지표, 위험 점수 및 모델 비중은 변경하지 않습니다. 메인 대시보드와 TXT 리포트에도 수급 요약을 표시합니다.

### 설정 순서

1. [KIS Developers](https://apiportal.koreainvestment.com/)에서 본인 계정의 실전용 OpenAPI App Key 및 App Secret을 준비합니다. 계좌·주문 API는 호출하지 않습니다. 실제 키를 GitHub에 올리지 마세요.
2. 관리자 `/admin` → 국내 증시 · 기업 실적 API → KIS 키 쌍 입력. [OpenDART](https://opendart.fss.or.kr/) 키는 기업 실적이 필요한 경우에만 입력합니다. 저장합니다. 기존 관리자 암호화 설정과 동일한 방식으로 보관하며 브라우저에 다시 반환하지 않습니다.
3. `/kr-market` → 시장 수급 수집을 실행합니다. 결과 및 원자료 관측일을 확인합니다. 첫 연결에서는 두 시장의 대표 지수와 순매수 단위를 [KRX 투자자별 거래실적](https://data.krx.co.kr/contents/MDC/MDI/outerLoader/index.cmd?screenId=MDCSTAT022) 및 증권사 HTS와 비교하세요. KRX/NXT 집계 범위 차이와 제공처 수정 가능성이 있습니다.
4. 관심종목에 6자리 종목코드와 표시명(직접 입력)을 등록합니다. 최대 20종목, 서버 DB에 보존됩니다. 종목별 갱신으로 종가 일봉 및 수급을 조회합니다. `상세`에서 차트와 동일 날짜의 수급, `편집`으로 이름/기업코드를 변경합니다. 삭제는 관심 목록에서만 제외하고 관측 이력은 유지합니다.
5. 기업 실적에서는 종목코드, 사업연도, 보고서 및 연결/별도를 선택합니다. DART 고유번호 공란이면 공식 `corpCode.xml` ZIP 목록에서 종목코드를 대조해 자동 검색합니다. 고유번호와 종목코드 일치 여부를 `company.json`에서 재확인합니다. `fnlttSinglAcntAll.json`의 표준 KRW 손익계산서 계정에서 실제 매출, 영업이익, 순이익, 기본 EPS, 전년 동기 증가율(전기 양수일 때), 영업이익률을 계산합니다. 분기/반기 보고서의 `thstrm_amount`는 해당 3개월, 사업보고서는 연간 금액입니다. 누적/예상 EPS/TTM과 구분합니다. 중복 충돌·계정 미확인·전기 적자 등은 공란 처리합니다. 재무정보는 사용자가 조회하는 방식이며 일괄 예약 수집은 아직 없습니다.
6. 자동 수집을 활성화하면 기존 매크로 수집 뒤 KIS 시장 및 관심종목 데이터도 갱신합니다. 키 미등록 시 생략하며 KIS 오류는 기존 매크로 결과를 변경하지 않습니다. 화면의 시장 수급 수집은 두 시장만, 종목 갱신은 해당 종목만 실행합니다. 기존 단일 작업 잠금을 이용합니다.

### API와 수집 정책

- KIS 시장 수급: `FHPTJ04040000`, `/uapi/domestic-stock/v1/quotations/inquire-investor-daily-by-market`, 공식 샘플 https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/inquire_investor_daily_by_market . 코스피 `0001/KSP`, 코스닥 `1001/KSQ`를 사용합니다. `*_ntby_tr_pbmn`은 백만원 기준으로 해석하여 100으로 나눈 억원 값을 표시합니다. **실제 키로 시장 코드와 단위 및 집계 범위의 대조 확인이 필요합니다.**
- KIS 종가 `FHKST03010100`, `inquire-daily-itemchartprice`(KRX/J, 원주가). 종목 수급 `FHPTJ04160001`, `investor-trade-by-stock-daily`(KRX/J). 공식 샘플 https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/ . 원주가 등락률은 분할/배당 영향 가능. 실시간 시세 아님.
- 오늘(한국 시간) 이전 날짜만 저장하고 주말 날짜를 제외합니다. 한국 공휴일 캘린더 완전성은 검증하지 않았으며 실제 API에서 제공한 관측일만 사용합니다. 초기 시장별 최대 4페이지 역방향 조회(60개 확보 목표), 이후 한 번씩 갱신하며 최대 400개 관측값 저장. 종목은 API 첫 배치만 저장하므로 기간이 부족할 수 있습니다. 날짜 누락·필수값 누락·중복 충돌을 검사합니다. 10일 초과 간격이나 n개 부족 시 누적값을 보류합니다. 이 검사는 공식 거래일 달력 검증이 아니므로 5/20/60은 정확히 거래일 전체가 아니라 **저장된 유효 관측일 수**입니다. 실데이터 수집 오류 시 기존 관측값은 남기고 오류 표시. 7일 넘게 지난 데이터는 오래됨 표시.
- 접근토큰은 프로세스 메모리에서 만료 전 재사용하고 재발급 최소 60초 제한을 둡니다. 재시작하면 캐시는 소실되므로 KIS 토큰 발급 제한에 걸리면 잠시 후 다시 시도하세요. 모든 외부 요청은 고정 호스트, 리다이렉트 차단, 요청 시간 제한 및 순차 호출을 사용합니다. API 사용권/호출량·데이터 재배포 조건은 본인의 계약 및 제공처 문서를 확인하세요.
- OpenDART 공식 가이드: [기업 고유번호](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019018), [기업개황](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS001&apiId=2019002), [전체 재무제표](https://opendart.fss.or.kr/guide/detail.do?apiGrpCd=DS003&apiId=2019020). 기업목록 메모리 캐시 24시간, 압축/해제 크기 제한과 XML 엔티티 거부.
- 신규 코드: `app/kr_market.py`(읽기 전용 수집·캐시·검증·API), `app/static/kr-market.html/js/css`, `app/static/kr-pulse.js`(메인 요약). 신규 DB 테이블 `kr_market_cache`, `kr_market_watch`는 최초 기동 시 자동 생성됩니다. 4.0 DB·설정은 동일 경로 유지 시 보존됩니다. 관심종목 및 시장 자료는 DB에 일반 데이터로 저장됩니다. 외부 호스팅은 전체 인증과 HTTPS를 유지하세요.
- 아직 미구현: 당일 장중 수급, 순매수 상위 종목 전체 시장 랭킹, 선물·프로그램매매, 공매도/대차, 해외 개별 종목, 애널리스트 예상 EPS/적정가 자동 산출, 뉴스 AI/알림. 기존 모델은 검증되지 않은 가설이며 국내 수급을 위험도에 합산하지 않습니다. OpenDART 실제 기본 EPS를 예상 EPS에 자동 대입하지 않습니다.


## 13. 4.2 자금 흐름 탐색: 장중 가집계와 관심종목 업종 비교

- 메뉴 **수급 순위 · 업종** (`/kr-insights`)에서 코스피/코스닥, 외국인/기관, 순매수/순매도를 선택한 후 수동으로 조회합니다. 기존 KIS 실전 키를 사용하고 별도 API 키는 필요하지 않습니다. 관리자 인증이 필요합니다.
- 공식 KIS `FHPTJ04400000`, `/uapi/domestic-stock/v1/quotations/foreign-institution-total`(국내기관_외국인 매매종목가집계)를 사용합니다. 시장 `0001`/`1001`, 금액 정렬 `1`, 순매수/순매도 `0`/`1`, 투자자 외국인/기관 `1`/`2`. 공급처가 반환한 유효 종목 중 선택 투자자의 순매수 거래대금(백만원 가정, 100으로 나눠 억원 표시)으로 부호 확인 후 최대 30개를 정렬합니다. 실 API 연결 및 금액 단위는 HTS와 대조해야 합니다.
- 장중 가집계는 증권사 추정 자료로, 확정 일별 수급이 아닙니다. 집계일/시각이 응답에서 확인되지 않으므로 조회 시각만 표시하고, 당일 확정값으로 저장하거나 모델 점수에 합산하지 않습니다. 평일 10:00~15:30 KST에만 수동 호출을 허용하며 실제 휴장일과 특별 거래시간은 별도 확인해야 합니다. 응답 없음은 순매수 0으로 해석하지 않습니다. KIS 공식 샘플: https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/foreign_institution_total . HTS 가집계 설명: https://securities.koreainvestment.com/pro_help/6449.html .
- 동일 조건 조회는 최대 60초 동안 메모리 캐시 재사용, 서로 다른 요청은 최소 3초 간격으로 제한합니다. 인증 키 변경 시 기존 캐시 재사용 금지. 조회 오류/조건 변경 시 화면의 이전 순위를 지웁니다. 기존 KIS 토큰 재사용, 고정 호스트, 시간 제한 및 전역 수집 잠금을 이용합니다. 데모 모드는 가상 종목만 반환하고 외부 호출하지 않습니다.
- **관심종목 수급 비교**는 최대 20개 서버 등록 종목에 대해 1/5/20/60개 공통 관측일을 기준으로 외국인·기관·개인 누적 금액을 비교합니다. 코스피·코스닥의 최근 관측일 목록이 일치하고 신선한 경우에만 계산합니다. 시장 관측일 연속성 검사(최대 10일 간격)는 공식 거래일 달력 검증이 아닙니다. 종목별 해당 날짜 자료 누락/오류/오래됨은 제외 내역에 표시하고 0으로 채우지 않습니다. 원주가 변화율은 같은 기간 시작 직전 관측일 및 종료일 종가가 둘 다 있을 때만 표시하며 배당·분할 효과가 포함될 수 있습니다.
- 외국인·기관 모두 누적 순매수인 종목 필터, 투자자별 정렬, 업종 태그를 제공합니다. **제외 종목 및 업종 태그 설정**을 열어 분류를 선택하면 즉시 비교하며 해당 브라우저에 저장합니다. 다른 PC/휴대폰에는 자동 동기화되지 않습니다. 업종별 히트맵은 직접 분류한 관심종목 표본 합계이며 KRX 공식 업종 전체 수급이나 시장 전체 순위가 아닙니다. 누락 종목 수 및 포함/등록 수를 확인하세요. 동반 순매수 필터는 종목 표에만 적용됩니다. 업종 히트맵은 포함 가능한 관심종목 전체를 표시합니다.
- 신규 파일 `app/kr_insights.py`, `app/static/kr-insights.html/js/css`, `tests/test_kr_insights.py`. API `POST /api/kr-insights/ranking`, `POST /api/kr-insights/watch`는 기존 관리자 인증/Origin/헤더 검증을 적용합니다. 기존 DB 테이블과 설정 포맷은 변경하지 않습니다. 추가된 메뉴 외에 기존 38개 지표와 수급 모델, 예약 수집, 포트폴리오를 유지합니다.
- 한계 및 후속 개발: 시장 전체 **확정** 순매수 종목 순위 및 공식 업종 전체 집계, 휴장일 자동 판별, 선물/프로그램매매, 공매도/대차잔고, 배당 캘린더, 예상 EPS 자동 산출, AI 뉴스/알림은 이번 버전에 구현하지 않았습니다. 공급처 계약 및 데이터 이용조건을 확인한 후 연결해야 합니다.


## 14. 4.3 시장 압력 관측소

메뉴 **시장 압력 관측소** (`/kr-pressure`)에서 시장과 관심종목, 1/5/20/60개 저장 관측일을 선택합니다. 관리자 인증이 필요하며, **KIS 수동 수집**은 기존 실전 키를 사용합니다. 새로운 키나 DB 테이블은 필요하지 않습니다. 기존 거시경제 위험도 및 자동 수집 일정은 변경하지 않습니다.

### KIS 공식 API 연동 (실계정 검증 필요)
- 시장별 프로그램매매 종합현황 일별: `FHPPG04600001`, `comp-program-trade-daily`. KRX(J), KOSPI K/KOSDAQ Q. 차익 `arbt_smtm_ntby_qty`, 비차익 `nabt_smtn_ntby_qty` 원자료 수량과 합계를 표시합니다. 공급처 금액·수량 스케일을 실전 HTS에서 대조하기 전에는 금액 환산을 하지 않습니다. 공식 예제: https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/comp_program_trade_daily
- 선택 관심종목 공매도 거래 일별: `FHPST04830000`, `daily-short-sale`, KRX(J). 공매도 체결 수량과 같은 행의 전체 거래량을 이용한 비중을 표시합니다. 기간 비중은 공매도 수량 합계/거래량 합계×100입니다. 이는 공매도 순보유잔고와 다릅니다. 공식 예제: https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/daily_short_sale
- 선택 관심종목 대차거래 일별: `HHPST074500C0`, `daily-loan-trans`, 조회구분 3(종목). 신규/상환 주수와 잔고 주수 표시. 신규/상환은 기간 합계, 잔고는 마지막 값 및 기간 처음 대비 증감입니다. 잔고 자체를 합산하지 않습니다. 대차잔고 전부가 공매도로 연결되는 것은 아닙니다. 공식 예제: https://github.com/koreainvestment/open-trading-api/tree/main/examples_llm/domestic_stock/daily_loan_trans
- 오늘 제외, 최대 약 95일 요청 범위, 공급처 첫 배치만 저장. 최대 400개 관측값 보존, 차트 최대 60개 표시. 휴장일 자동 판별/완전한 거래일 수집 보장 없음. 7일 초과 또는 오류 시 기간 요약과 비교 보류. 수집 실패 시 이전 이력 유지. 기존 토큰 재사용, 단일 잠금, 최소 5초 수동 호출 간격, 고정 API 호스트 및 시간 제한 적용.

### KRX 수동 CSV 등록
자동 수집 규격을 확인하지 못한 두 지표는 사용자 확인을 거친 CSV만 등록합니다. [KRX Data Marketplace](https://data.krx.co.kr/contents/MDC/MAIN/main/index.cmd)에서 원자료를 확인한 뒤 프로그램 표준 헤더(빈 템플릿 다운로드 가능)로 변환하세요. KRX 원본 다운로드 CSV를 자동 인식하지 않습니다. 출처/상품 범위 및 단위는 서버에서 인증하지 못하며 사용자 등록 자료로 표시합니다.
- 코스피200 선물 전체 월물 투자자별 일별 순매수 계약: `date,foreign_contracts,institution_contracts,individual_contracts`. 현물은 코스피 전체 순매수 억원입니다. 동일 최신 관측일이고 양쪽 신선할 때 방향만 비교하며, 계약 수와 금액을 합산하거나 헤지/보유 포지션을 추정하지 않습니다. 코스닥과 선물 직접 비교는 보류합니다.
- 선택 관심종목 공매도 순보유잔고: `date,balance_qty,balance_pct` (잔고 주수, 비율 %). 공시 지연에 유의하세요. 자동 API 및 실제 잔고 실시간 조회가 아닙니다.
- YYYY-MM-DD 완료 평일 날짜, 정확한 헤더, 중복 없음, 수치 범위와 400행/200KB 상한 검증. 동일 날짜는 사용자 확인 후 교체됩니다. 데모는 합성값만 사용하며 외부 호출 및 CSV 등록을 차단합니다.

신규 모듈 `app/kr_pressure.py`, `app/static/kr-pressure.html/js/css`, `tests/test_kr_pressure.py`. `GET /api/kr-pressure`, `POST /api/kr-pressure/refresh`, `POST /api/kr-pressure/import`에 기존 인증/쓰기 Origin 및 헤더 검사를 적용합니다. 신규 지표는 기존 미국 위험 점수 및 모델 배분에 반영하지 않습니다. 프로그램매매와 투자자별 수급은 중복될 수 있어 합산하지 않습니다. 실 KIS API 및 실제 CSV 원자료는 배포 후 확인해야 합니다.


## 15. 4.4 기업 가치 관측소 / 배당 분석

- 국내 증시 메뉴에서 **보통주** 관심종목을 등록하고 `기업 가치 · 배당` (`/kr-value`)에 들어갑니다. 연결(CFS)/별도(OFS), 최근 5/10개 완료 사업연도를 선택합니다. OpenDART 키는 기존 관리자 설정을 사용합니다. 신규 키와 DB 마이그레이션은 필요 없습니다. 관심종목의 종가를 갱신하려면 기존 국내 증시 메뉴에서 종목 수집을 실행하세요.
- **OpenDART 공시 수집**은 선택 종목만 수동 조회합니다. `company`로 고유번호/종목코드 일치를 확인하고, 2015년 이후 사업보고서 `fnlttSinglAcntAll`(11011, 선택 연결/별도) 및 `alotMatter`(11011)를 연도별 호출합니다. 최신 연도가 미공시인 경우에도 임의값을 넣지 않습니다. `list.json`은 최근 365일, 최대 4페이지(페이지당 100건) 중 제목에 배당이 포함된 결과 최대 100건을 표시합니다. 공시 접수일은 배당 기준일이 아닙니다. 정정/철회 및 실제 배당 조건은 원문 링크에서 확인하세요.
- 연간 실적은 KRW 및 표준 XBRL ID, 동일 사업연도/보고서/접수번호를 검증합니다. 매출, 영업이익, 순이익, 기본 EPS, 영업이익률, 전년 대비 성장률(전년 양수일 때), 영업현금흐름, ROE와 FCF를 표시합니다. 연결 ROE는 지배기업 소유주 귀속 순이익/평균 지배기업 소유주 지분, 별도 ROE는 순이익/평균 자본입니다. FCF는 OCF에서 유형·무형자산 취득 현금유출 절댓값 합계를 차감합니다. 분모·항목 누락 및 상충 값은 공란입니다. 표준 ID 미사용·특수 업종·자본 구조에 유의하세요.
- 배당 이력은 사업보고서의 보통주 주당 현금배당금(DPS), 공시 현금배당수익률과 기업 전체 공시 현금배당성향을 표시합니다. 우선주와 합산하지 않으며 연간 보고서에 분기배당을 다시 더하지 않습니다. `stlm_dt`는 결산기준일이며 배당 기준일이 아닙니다. 주식분할·병합 전후 비교는 직접 확인하세요. 최신 유효 종가 대비 과거 연간 DPS 수익률은 예상 배당률이 아닙니다.
- **배당 일정**은 공시 원문 및 거래소 확인 후 접수번호/기준일/배당락일/지급일/회차별 DPS/예정·확정·취소를 수동 등록·수정·삭제합니다. 최대 100건, 날짜 순서 및 범위 검증, 기존 저장본 동시 수정 충돌 검사를 적용합니다. 자동 배당락일 및 지급일 추정, 원문 일정 자동 추출/검증은 하지 않습니다.
- **과거 밸류에이션 비교**는 `date,price,eps,bps` CSV를 등록합니다. 관측일 당시 공개된 동일 기준 EPS/BPS와 종가만 사용해야 합니다. 출처 및 분모 기준을 기록하고 기존 비교 자료 전체 교체에 동의해야 합니다. 최대 400행, 2015년 이후 완료 평일, 중복·누락·범위 검증, 사용자 확인(원자료 미검증) 표시. 적자 EPS에는 PER이 공란입니다. 과거 공시 정정값을 이용한 자동 역사적 PER/PBR 계산을 제공하지 않습니다. 차트는 최근 30개 관측값, 표는 전부 표시합니다.
- **가치평가 시뮬레이터**는 최신 유효 종가와 가장 최근 요청 사업연도의 정상 수집된 연간 실제 EPS/DPS/영업이익을 버튼으로 적용할 수 있습니다. BPS·예상 EPS·평균 투하자본은 직접 입력하고 보수/기준/낙관 PER/PBR 배수를 지정합니다. 적정가=EPS×PER 또는 BPS×PBR, 현재가 대비 괴리, 입력 기준 PER/PBR, DPS/EPS 단순 성향, 배당수익률, 가정 ROIC=영업이익×(1−가정세율)/평균 투하자본을 계산합니다. 적자 EPS나 미확인 입력은 해당 계산을 보류합니다. 기업가치 예측 및 매매 신호가 아닙니다.
- **배당 재투자 비교**는 초기금액, 연간 배당수익률, 배당 제외 가격 수익률, 배당세율, 기간(1~30년)을 가정합니다. 연초 주식 평가액 기준 세후 배당을 연말 재투자하거나 무이자 현금 보유합니다. 소수주 가능, 가격·수익률 일정, 수수료·환율·양도세 제외. 실제 성과나 역사적 백테스트가 아닙니다.
- 같은 날 성공한 공시는 재사용(UTC 저장일과 KST 조회일 비교이므로 자정 전후 캐시 재사용이 짧아질 수 있음), 체크박스로 정정 공시 재조회. 종목별 30초 제한 및 기존 전역 수집 잠금, 고정 호스트와 연결 제한을 사용합니다. 공시 조회를 시작하는 총 시간은 80초로 제한하나 이미 시작된 네트워크 호출은 완료/타임아웃까지 기다릴 수 있습니다. 실패/보류 상태를 표시하고 이전 자료는 유지합니다. 수동 수집은 기존 매일 거시경제 수집 일정에 포함하지 않습니다.
